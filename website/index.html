Performance

Fast from the first click

No sign-in, no cloud sync, no waiting. Every number here was measured, and the benchmark is a script you can run yourself.

  • 0.3 s from launch to a ready window, and under half a second with 6,000 requests
  • 16× faster than Postman's collection runner on 500 requests with scripts and tests
  • 0 accounts, sign-ins or cloud syncs between you and your first request

Built for real APIs

Less setup. Fewer 401s. No copy-pasting tokens.

Tokens that refresh themselves

Point a collection at its login request once. Before every call, HttpDash checks the token: if it's missing or about to expire, it runs the login first, saves the new token, and sends your request. If a server still answers 401, it refreshes and retries.

  • Reads the token from any JSON path, such as data.jwToken
  • Knows when a JWT expires, or uses expires_in
  • Works the same in the runner, monitors and the CLI

Environments from your service registry

Connect Consul, Eureka, Kubernetes or your own JSON endpoint, and HttpDash creates an environment with one variable per service, like {{orders_url}}. Re-sync whenever services move: addresses update, new services appear, and the variables you added yourself stay put.

  • Healthy instances only, with tag and namespace filters, or every pod behind a Kubernetes Service
  • Point it at an OpenAPI document and every operation becomes a request, kept in step with the spec
  • Each new version of the spec is compared with the last: review what changed, then apply it, with your own edits kept

Find the slow instance, or the slow payload

Send to each instance of a service in turn and HttpDash counts what every one of them answers: requests, p50 and p95 times, errors. Give a request several payloads and it counts those too, so a pod that is slow for everyone can be told apart from an order that is slow on every pod.

  • Flags instances that are slow or failing, and payloads that are worse than their siblings
  • Behind a load balancer, counts by the header that names who answered, such as X-Served-By
  • Export the report to Excel, CSV, PDF, an image or Markdown

Compare every instance of a service

One click sends the same request to every instance behind a service and puts the answers side by side. HttpDash finds the instances in your registry, or in every address the host name resolves to, and points out the one that answered differently: an old version, a missing field, a different state.

  • Instances come from Consul, Eureka, Kubernetes or DNS, refreshed when you compare
  • Tells an odd one out from a split, and ignores dates, timestamps and IDs made on the spot
  • Ignore the headers and JSON paths that are meant to differ

Let AI agents work in HttpDash

Claude and other AI agents can use HttpDash the way you do: find requests, send them, add and update them, start runs and read the results, and look at the screen. They connect through an OpenAPI document or MCP, on your own computer only, and you decide what they are allowed to do.

  • 30 operations, described in an OpenAPI 3.1 document, or httpdash mcp for MCP clients
  • Separate permissions to read, run, edit, use the screen and see secrets
  • A status bar light while an agent works, and a history of every call it made

Every version you sent, and a warning when the spec moves on

Each request you send by hand is kept as a version, with the response it got. Switch back to one in a click, rename it, tag it and find it in search. When the OpenAPI document the request came from changes, HttpDash tells you what no longer fits before you send it.

  • Versions keep the URL, parameters, headers, body and the response
  • Flags missing required parameters and fields, unknown ones, and values outside an enum
  • Collection runs don't add versions, so the list stays yours

Find any request by name, URL or tag

Give requests as many tags as you like, and HttpDash suggests the ones you already use. The search box knows every name, URL, method and tag in your workspace, so you pick from a list instead of remembering what you called it.

  • Combine tags with text, such as #smoke and “pay”
  • Pick what a run includes from the folder tree, or by tag
  • Run only the tagged requests in CI with httpdash run backup.json --tag smoke

Send exactly what you mean

Requests leave from a native HTTP client, not a browser, so every header goes out as typed, including Referer, Origin, User-Agent, Host and Cookie. The timeline shows the exact request that was sent and how long each step took.

  • JSON, XML, form-data with files, URL-encoded, binary and GraphQL bodies
  • Basic, Bearer, API key, Digest, OAuth 2.0 and AWS Signature auth
  • Paste a cURL command into the URL bar to import it

Read any JSON response as a table

Switch a response to Table and arrays of objects become sortable tables, with a column for every key. Nested objects and arrays open in place, so you can drill into items or address without leaving the row.

  • Filter rows as you type; sort any column
  • Export to Excel, CSV or a PNG image, following your filter and sort
  • Virtual rendering: 100,000 rows open in about a tenth of a second

WebSocket, with a live message log

Connect to ws:// and wss:// servers, send text or JSON, and watch everything that goes each way with timings and sizes. The handshake carries your headers and the collection's auth, so authenticated sockets just work.

  • Saved messages you can resend with one click
  • Click any message to see it pretty-printed
  • Client certificates, your proxy and {{variables}} apply

Streaming responses, as they happen

When an API streams Server-Sent Events, as AI APIs do, HttpDash shows each event the moment it arrives instead of waiting for the end. Stop whenever you like and keep what came in.

  • Works with any method and body, so streaming POSTs just work
  • An Events view with timings, names and ids
  • Parsed exactly the way browsers do

Run the same collections in CI

  • Exit code 1 on any failed test or request

Security & privacy

Your requests, your machine, your rules

HttpDash has no account and no cloud sync. Collections, environments and history live in a folder on your computer.

  • Lock it with your directory

    Require an LDAP sign-in to open the app, limit it to certain users or a group, and lock it after a period of inactivity. While locked, the app shows no data at all.

  • Find secrets before they leak

    The secret scan spots keys, tokens and passwords typed straight into requests and moves them into masked variables with one click.

  • Share without credentials

    Exports can leave out every secret, token and password, while keeping {{variable}} references intact.

  • A record of what happened

    A local audit log notes sign-ins, exports, imports, runs and requests, keeping only method, host, path and status.
